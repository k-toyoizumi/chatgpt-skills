# 共通設定更新時の利用先確認

要点：更新担当Agentが意味上の整合性を確認し、Git hookが読込案内の同期漏れを補う。

## 更新担当Agentの手順

1. 正本の変更差分を特定し、`python3 scripts/sync_consumers.py --check` で利用先と案内の差分を確認する。
2. 対象は既定で正本と同じ親ディレクトリ直下にあり、AGENTS.mdに正本の絶対パスが記載されたプロジェクト。別の配置は `--projects-root /path/to/projects` を複数指定できる。対象なし・読めない探索先を全件成功としない。
3. 変更した規約に直接関係する各案件のAGENTS.md・仕様・参照を読み、矛盾、古い複製、参照切れ、必須読込の漏れを確認する。全ログや全コードを再処理しない。案件固有の現在状態やパス一覧は共通Rules / Skillsに埋め込まない。
4. `--apply` で読込案内を同期し、意味上の修正は必要な箇所だけAgentが行う。既存の未コミット変更を保持し、管理区画外の自動置換はしない。重大な方針変更・予算・承認条件の緩和はユーザー判断を求める。書込権限が必要なら通常の権限承認を使う。
5. `--check` と変更箇所の参照検査を再実行する。機械検査、意味上の確認、実会話での読込確認を区別して報告する。Agent側の環境から別会話へ指示を強制注入したとは扱わない。

## Gitによる自動同期

この正本で一度だけ `git config core.hooksPath .githooks` を実行する。既存のhooksPathや実働hookがある場合は上書きせず統合する。解除は、この設定が `.githooks` の場合に限り `git config --unset core.hooksPath`。clone先では別途有効化が必要。

commit・merge/pull・checkout後にスクリプトが実行され、各AGENTS.mdの `chatgpt-skills:begin/end` 内だけを更新する。案件側のcommit/push、実験、API呼出しは行わない。同期値はRules / Skills等の内容ハッシュで、レビュー済み印ではない。対象の未コミット変更は保持し、マーカー不正・権限不足はエラーとして表示する。hook失敗は既に成功したGit操作を取り消さない。

Git操作を伴わない編集にもAgentの上記確認義務を適用する。常駐監視・定期実行・自動pullは導入しない。Git hookは機械的な読込案内の同期だけを担い、規約同士の意味上の衝突の自動解決を保証しない。

既存セッションは以前の指示を保持し得るため、案件側で新しい会話を開始して読込と回答を確認する。
