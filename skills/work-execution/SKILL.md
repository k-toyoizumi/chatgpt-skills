# 計画の実行

- 計画、最新の指示、既存成果物・検証記録を照合する。再開時は変更の影響を受けた完了工程と未完了工程を特定する。
- 各工程の前提を確認し、着手可能な工程を進める。並列実行が許可されている場合は、作業範囲が衝突しない工程を利用可能な担当枠で同時に開始する。実行中に前提がそろった工程は、無関係な工程の完了を待たずに開始する。枠が限られる場合は、後続の着手や全体の完了を左右する工程を優先する。
- 委譲時は計画の担当・モデル・effort・編集範囲を確認する。同じ担当の再利用時は変更点と次の完了条件を渡す。委譲や並列実行ができない場合は、実行可能な担当と順序に調整して進める。モデルの選択は正本の `rules/model-and-cost.md` に従う。
- 各担当の成果物と検証結果を回収し、後続が使う前提を満たしたことを確認する。複数の成果が合流する工程では、統合後の成果も検証する。
- 成果物を計画の完了条件に照らす。コードは該当動作、文献比較は原典と比較条件、資料は依頼項目と出典など、観察した結果を残す。保存済み計画では進捗・判断理由・残作業を差分更新する。
- 局所的な失敗は原因を切り分けて再試行し、影響のない作業を続ける。目的・予算・重要な前提を変える必要が生じたら、その判断をユーザーに戻す。
- 終了時に成果物、確認結果、残る制約を示す。実験結果や重要な判断を説明する場合は explain-for-decisions を使う。独立レビューが明示依頼されている場合は background-critical-review の結果も統合する。

## 計画と進捗を回答に載せる

- 着手・再開、工程の切り替わりや待ちが発生したとき、進捗を尋ねられたとき、最終回答で、計画の参照先と以下の進捗欄を示す。他の中間報告は既存の共有頻度に従う。短い実行は最終回答にまとめてよい。
- 参照先は実際に読んだ計画の名称とリポジトリ相対パス、または確認済みの共有リンク。会話の計画なら該当する発言や見出しを示す。親計画の一部を実行している場合は、親計画と対象工程を明記し、バーがどちらを数えているか示す。
- バーは計画全体の工程数を分母、完了条件を確認した工程数を分子とする。工程の一覧と同じ単位で数え、親工程とその内訳を二重に数えない。10枠のうち `10 × 完了数 ÷ 全工程数` の整数部分を塗り、割合も整数に切り捨てる。途中・待機中の工程は完了数に入れない。総数が決まっていない間は「完了 n 件／全体未確定」と表示し、割合とバーを省く。計画の改訂で総数が変わったら理由を一言添える。
- 各工程を計画上の ID と短い名前で、「完了」「現在」「未完了」のいずれかに載せる。並行作業は「現在」にまとめ、未着手・依存待ち・停止中は「未完了」に置き、必要なら理由を添える。空の欄は「なし」とする。再開時や最終回答では、計画の記録と確認結果を照合してから表示する。

例

```text
計画　「検索改善」 docs/plans/search.md
進捗　[████░░░░░░] 2/5 工程完了（40%）
完了　A 現状調査、B 仕様確定
現在　C 検索処理を実装
未完了　D 回帰検証、E 文書更新
```
