# エージェント設計の事前調査

1. **変更の範囲を確認する。** 目的、期待する挙動、既存実装、対象のエージェントとバージョン、実行環境、権限、運用上の制約を把握する。挙動に影響しない誤字・整形だけなら、調査を省く。
2. **方針を決める前に公式資料と公開実例を調べる。** OpenAI、Anthropic、Google など、対象製品と比較候補の開発元の現行ドキュメント・推奨手順を確認する。仕様は利用バージョンで確認し、複数製品に共通する判断では関連する複数社を比較する。広く参照・採用されている公開実装、運用事例、評価も調べ、更新状況、実装や測定の公開、再現性、自分たちの前提との一致を確認する。普及度は調査候補の選定に使う。広範な文献レビューも必要な場合は `research-survey` を参照し、集めた資料を共有する。
3. **現行方式と変更案を比べる。** 目的を満たす最小の変更を選ぶ。指示環境の見直しでは、実際に読まれるファイルの優先順位・範囲・量・重複を確認する。常時必要な制約と参照先は入口に、条件付きの手順は Skill に、対象領域だけの規約は対応する指示ファイルに置く。機械的に判定できる要件は既存のテスト、CI、権限設定、フックを検討する。Skill の重複は名前、発動条件、本文、実際の配置を照合し、参照先と既存の利用者も確認する。
4. **確認結果を残す。** 小修正では該当ケースを確認し、設計や権限への影響が大きい変更では代表ケースと失敗ケースで変更前後を比べる。Skill を変更した場合は対象の依頼と対象外の依頼を確かめ、静的な検査と実セッションでの発動確認を区別する。採用理由、環境向けの調整、根拠のリンク、検証結果を既存の設計メモ・PR・回答のいずれかに残す。外部資料や実行環境を確認できなかった場合は、未確認事項と進めた範囲を記す。
