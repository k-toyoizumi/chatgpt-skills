# 品質ゲート

## 内容（必須）
- 学習目標と本文が一致 / 定義が正確 / 重要な主張に出典がある。
- 略称の初出が「正式名称→略称」で、重要な専門用語・記号の意味が最初の使用時に説明される。**各章で**Q/K/Vなどの基本記号を再確認する。数式の全変数・添字・単位・行列の形状を必要に応じて定義する。
- 図・表・見出し・演習で略称だけが先に現れない。図表の単体閲覧に必要な凡例・ラベルがある。
- 数式、図、具体例が矛盾しない。厳密式と模式図を混同しない。
- 図解をただ増やすのではなく、説明価値のあるものだけ残す。
- すべての図・表は自動採番され、本文中の `@fig-...` / `@tbl-...` 参照が実リンクとして解決する。比較表は対象・単位・前提の比較可能性を確認する。
- 表を小型数値行列／長文比較／幅広い表に分類。行・列の主体と値の向きを見出し・キャプションで明示し、左上セルに長い軸説明を詰めない。表ごとに適切な幅・折り返しを選ぶ。
- 2問以上の理解確認。誤答理由または代表的な勘違いに言及。

- 章の単位が適切で、章ごとの独立したページに切り分けられている。

## 技術（必須）
- `SKILL.md` の name と description、参照ファイルの整合
- すべての .qmd が `_quarto.yml` の目次に含まれ、素材参照が有効。章・節階層の折りたたみ、章リンク、前後章ナビゲーション、**章をまたぐ**図表参照が有効。
- PCの左サイドバーと右TOC、スマホの格納式章メニューを確認。
- Quarto CLIがある場合は `quarto render` 成功、HTMLのページ移動/図/数式が表示される
- 375px程度のスマートフォンとデスクトップで可読性を目視で確認
- 表ヘッダーと本文セルの列境界が一致し、数値表が不必要に全幅へ引き伸ばされず、長文表が折り返し、幅広い表はコンテナ内のみスクロールすることを実ブラウザで確認する（`scripts/test_tables_layout.py` はCSS回帰テスト）。Quarto出力とプレビューは別判定とする。
- アニメーションは原則なし。内容と無関係なJSを避ける

## 報告区分
- `PASS`：実際に検証して成功
- `FAIL`：実際に検証して失敗
- `NOT RUN`：環境や時間のため未実行

Quartoの有無を問わず、未実行なのにレンダリング成功と記載しない。
