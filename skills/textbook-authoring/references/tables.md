# 表・比較表・数値行列の制作規則

## 表を選ぶとき
- 複数対象を同じ評価軸で比較するとき、または行・列で関係や数値を整理するときに使う。文章で十分な場合は表にしない。
- **表の意味的な型を先に判定する**。短い利得表・混同行列・数値表は `tb-table-compact`、文章の多い比較表は `tb-table-comparison`、多数列で最小可読幅が必要なときだけ `tb-table-wide`（比較表と併用可）。
- 全表共通の `width:100%`、等幅列、大きな `min-width`、`white-space:nowrap` を禁止。表の幅は情報量で決め、本文の横幅を無意味に埋めない。
- QuartoのMarkdown pipe table、`{#tbl-...}` のキャプション、本文の `@tbl-...` 参照を基本とする。番号を手入力しない。幅指定が必要なら、その**表だけ**CSSクラスや列幅指定を使う。

## 行・列・数値の意味（重要）
- 行列では行の主体（誰が行動するか）を第1列の見出しに、列の主体を各列見出しに記す。例：`自分の行動`／`相手：防御`／`相手：仕掛け`。行ラベルは短く維持する。
- 「行の主体＼列の主体」のような長い説明を**左上の1セルだけ**に押し込まない。説明はキャプションや表の直前の文章へ分散させる。
- 行・列の方向、値の主体、単位、符号、前提、出典を明示する。ゲームの利得表なら「数値は自分の利得（点）」などと記し、相手の利得と混同させない。
- 見出し行とデータ行の列境界が揃い、見出しが実データに対応することを確認する。図表単独でも解釈できる正式名称・略称・記号説明を添える。

## サイズとレスポンシブ
- **小さな数値行列**：内容に応じた幅（`width: max-content` 相当）を使い、短いセルのみ折り返さない。長い第1列が幅を支配しないようにする。必要なら列ごとの幅を指定する。
- **長文比較表**：セル内の自然な折り返しを許し、項目数に応じて幅を使う。すべての列を等幅にしない。
- **多数列の幅広い表**：必要なときに限り個別の最小幅を指定し、表のコンテナ内部を横スクロール可能にする。表を縮小表示して文字を読めなくしない。**ページ全体**を横にはみ出させない。
- 表ヘッダーは `<th>` 相当の正しいHTML構造にし、行見出しを意味的に区別する必要がある複雑な表では `scope="row"` 等も検討する。背景色だけに情報を依存させない。

## Quartoの記述例：短い利得行列

```markdown
@tbl-payoff-example は、行が自分、列が相手の行動に対応する。

::: {.tb-table-compact}

| 自分の行動 | 相手：防御 | 相手：仕掛け |
|:--|--:|--:|
| 攻撃 | +2 | -1 |
| 待機 | 0 | +1 |

: 行＝自分の行動、列＝相手の行動。数値は自分の利得（点）。 {#tbl-payoff-example}

:::
```

## Quartoの記述例：長文比較

```markdown
@tbl-methods のように、比較対象と条件を揃える。

::: {.tb-table-comparison}

| 方式 | 強み | 制約 |
|:--|:--|:--|
| A | 特定条件では高精度 | 実装が複雑で計算コストが高い |
| B | 推論が速い | 近似誤差が許容できる範囲でのみ利用可能 |

: 手法の比較（同じ入力条件を仮定）。 {#tbl-methods}

:::
```

Quartoの表キャプションと fenced div は組み合わせられる。表を参照するIDは**表のキャプション**に置き、単なる装飾用の外側divに `tbl-` IDを重複させない。Quarto以外のプレビューでも採番とリンクを確認する。

## 検証・報告
1. 元の `.qmd`、テンプレートCSS、代替レンダラーのCSSを修正する。生成されたHTMLだけのパッチでは再生成後に失われる。
2. PCおよびスマホの実レンダリングで、列見出しとセルのx座標／境界、列幅、余白、折り返し、主体・値の向き、キャプション、画面全体の横スクロールの有無を確認する。
3. Quarto正式出力と代替レンダラーで表示を比較し、両者のPASS/FAIL/NOT RUNを区別する。**HTML/CSSの静的確認のみで「目視確認済み」と報告しない**。
4. 代替レンダラーにしか適用できない修正は限界を明記する。数値・意味の変更は別途検証する。
