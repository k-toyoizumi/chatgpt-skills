# Core Rules

## 適用範囲

継続的な Web / Sites 開発、情報収集・レポート、自動化、研究支援、Agent 開発など、長期的・反復的な作業に適用する。

日常の短い質問や単発の軽い作業には、必要のない Rules / Skills を読み込まない。

## 共通原則

1. **LLM を呼ばなくてよい処理は通常コード・通常ツールで行う。**
2. **必要な情報だけを Context に入れ、過去全文を毎回読み直さない。**
3. **外部 State を正本とし、ChatGPT Memory は安定した routing / preference に限定する。**
4. **全件再生成より差分更新を優先する。**
5. **必要十分な最小 model / reasoning effort から開始し、必要時だけ上げる。**
6. **検証に失敗した成果物を正常版として公開しない。**
7. **機械的に判定できるルールは、LLM の判断ではなくテスト・schema・コードで担保する。**

## 指示の優先順位

リポジトリ内の運用上は、原則として次の順で優先する。

1. ユーザーの最新の明示的な指示
2. 対象タスク・プロジェクト固有の仕様
3. 対象タスクに適用する Skill
4. このリポジトリの共通 Rules

競合した場合は、より新しく、より具体的な指示を優先する。

## 品質とコストの優先順位

**Correctness / Security → Reuse → Minimal Context → Minimal Model/Effort → Visual polish**

コスト削減のために correctness・security・必要な検証を省略しない。

主な節約対象は以下。

- 重複推論
- 不要な全文読み込み
- 不要な high reasoning effort
- LLM で行う必要のない機械的処理
- 変更のないデータの再処理
